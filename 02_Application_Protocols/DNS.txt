DNS — DOMAIN NAME SYSTEM
Источник: Protocol Explorer, карточка DNS.

ПО САЙТУ
Сценарий:
1. Ask the resolver — ноутбук передаёт вопрос резолверу.
2. Root server — указывает направление к .com.
3. .com TLD server — указывает к example.com.
4. Authoritative server — возвращает фактический ответ.
5. Answer & cache — ноутбук получает адрес, ответ кэшируется.

ПОЯСНЕНИЕ
DNS — распределённая иерархическая система имён и ресурсных записей. Stub resolver на устройстве обычно отправляет запрос рекурсивному резолверу. При отсутствии кэшированного ответа рекурсивный резолвер может обращаться к root, TLD и authoritative серверам.
A — запись IPv4, AAAA — IPv6, MX — почтовые серверы, CNAME — каноническое имя, NS — серверы имён, TXT — текстовые данные.
Кэширование ограничивается TTL записи. Ответ может быть получен из кэша и в таком случае рекурсивная цепочка не выполняется целиком.

ПО САЙТУ НЕ УТОЧНЕНО
В коротком списке шагов не показаны все типы DNS-запросов, транспортные детали и конкретные TTL.

СВЯЗАННЫЕ ТЕМЫ
DoH, DNSSEC, DHCP, HTTP, SMTP.
