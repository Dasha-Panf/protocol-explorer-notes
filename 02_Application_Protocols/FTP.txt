FTP — FILE TRANSFER PROTOCOL
Источник: Protocol Explorer, карточка FTP.

СЦЕНАРИЙ САЙТА
1. CONTROL CONNECTION — порт 21, текстовое управление.
2. LOG IN — USER и PASS видны наблюдателю незашифрованного канала.
3. PASSIVE MODE — сервер сообщает порт для передачи данных.
4. DATA CONNECTION — создаётся второе TCP-соединение.
5. THE FILE ARRIVES — закрытие data connection завершает передачу.
6. QUIT — закрывается управляющее соединение.

ПРИНЦИП РАБОТЫ
FTP разделяет управляющий канал и канал передачи данных. В active mode сервер инициирует data connection к клиенту; в passive mode клиент сам подключается к порту, который сообщил сервер. Passive mode обычно легче использовать за NAT и межсетевыми экранами.
TCP 21 — стандартный порт управляющего канала. Порт данных зависит от режима, сервера и диапазона пассивных портов.
Обычный FTP передаёт команды, пароль и файлы без шифрования. FTPS — FTP, защищённый TLS. SFTP — передача файлов через SSH, это другой протокол и не является разновидностью FTP.

РИСКИ
Не использовать обычный FTP для передачи секретов через недоверенную сеть. Для защиты предпочтительны SFTP или FTPS с корректной проверкой ключей/сертификатов.

СВЯЗИ
TCP, NAT, firewall, FTPS, SFTP.
