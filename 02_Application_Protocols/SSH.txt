SSH — SECURE SHELL
Источник: Protocol Explorer, карточка SSH.

СЦЕНАРИЙ САЙТА
1. SAY HELLO — версии передаются в открытом виде.
2. AGREE ON ALGORITHMS — KEXINIT перечисляет алгоритмы; выбирается первое совпадение.
3. KEY EXCHANGE — формируются общие ключи и проверяется host key.
4. LOG IN WITH A KEY — подпись вместо отправки секрета.
5. OPEN A SESSION — несколько каналов внутри одного соединения.
6. TYPE A COMMAND — ввод передаётся пакетами.

ПРИНЦИП РАБОТЫ
SSH (Secure Shell) обеспечивает защищённый удалённый доступ к командной оболочке, туннелирование портов и передачу файлов. Обычно использует TCP порт 22.
На начальном этапе стороны обмениваются идентификаторами версий и списками алгоритмов. Затем выполняется key exchange, стороны создают общий секрет и проверяют ключ хоста сервера. После установки защищённого транспорта пользователь проходит аутентификацию: например, паролем или открытым ключом.
Проверка host key — критически важная часть защиты от подключения к поддельному серверу. Если клиент без проверки принимает любой ключ, защита от man-in-the-middle ослабляется.
Одно SSH-соединение может содержать несколько логических каналов, например shell, exec, SFTP и port forwarding.

СВЯЗИ
TCP, SFTP, TLS, VPN, публичные/приватные ключи.
