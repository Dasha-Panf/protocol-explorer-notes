HTTP FORWARD PROXY — FORWARD PROXY AND CONNECT
Источник: Protocol Explorer, карточка HTTP Proxy.

СЦЕНАРИЙ САЙТА
1. PROXY SETTINGS — браузер направляет запросы прокси.
2. TO THE PROXY — TCP-соединение к порту 8080.
3. THE WHOLE URL — GET http://www.example.com/.
4. PROXY FETCHES IT — прокси создаёт собственное соединение к серверу.
5. PAGE PASSED ON — прокси передаёт страницу клиенту.
6. HTTPS: CONNECT — CONNECT www.example.com:443.
7. IN THE TUNNEL — прокси копирует поток, не читая содержимое TLS-туннеля.

ПРИНЦИП РАБОТЫ
Forward proxy действует от имени клиента и пересылает запросы к удалённым серверам. В обычном HTTP proxy клиент может передать полный URL в request line. Прокси выполняет запрос от своего имени и возвращает полученный ответ клиенту.
Для HTTPS часто используется метод CONNECT. Клиент просит прокси установить TCP-туннель к целевому host:port, после чего TLS-соединение устанавливается между клиентом и целевым сервером через этот туннель. Прокси пересылает байты, не расшифровывая TLS-содержимое.
В корпоративных сетях может использоваться TLS interception: прокси завершает TLS и показывает клиенту сертификат, выпущенный корпоративным CA. Это другой режим, требующий доверия клиента к корпоративному корневому сертификату.
8080 — часто встречающийся порт прокси, но он не является обязательным стандартом порта HTTP proxy.

СВЯЗИ
HTTPS, TLS, SOCKS5, reverse proxy.
