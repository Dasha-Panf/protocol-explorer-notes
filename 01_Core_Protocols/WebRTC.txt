WEBRTC — BROWSER VIDEO CALLS
Источник: Protocol Explorer, карточка WebRTC.

СЦЕНАРИЙ САЙТА
1. JOIN THE CALL — соединение через signalling server.
2. PUBLIC ADDRESS? — запрос к STUN-серверу.
3. THE OFFER — SDP-описание передаётся через сервер.
4. THE ANSWER — браузер второго участника отвечает.
5. PUNCH THROUGH — проверяются прямые соединения между участниками.
6. DTLS HANDSHAKE — формируются ключи для медиа.
7. MEDIA FLOWS — аудио и видео идут напрямую.
8. PEER TO PEER — используется альтернативный путь, когда прямое соединение невозможно.

ПРИНЦИП РАБОТЫ
WebRTC — набор браузерных API и протоколов для real-time аудио, видео и произвольного обмена данными. Сигнализация, то есть доставка SDP offer/answer и ICE-кандидатов, не задаёт единственный обязательный серверный протокол: приложение реализует её самостоятельно.
SDP (Session Description Protocol) описывает медиа-параметры: кодеки, направления потоков, адреса и другие характеристики. ICE собирает и проверяет кандидаты сетевых маршрутов. STUN помогает узнать адрес и порт, которые видны снаружи NAT. TURN предоставляет relay, если прямой путь невозможен.
Для защиты медиапотока WebRTC использует DTLS-SRTP: DTLS помогает согласовать ключи, SRTP защищает RTP-медиа. Для данных может использоваться SCTP поверх DTLS.
Важная оговорка к шагу сайта: peer-to-peer не гарантирован. В корпоративных сетях, строгих NAT и firewall часто требуется TURN relay.

КОГДА ПРИМЕНЯЕТСЯ
Видеозвонки, голосовые звонки, демонстрация экрана, совместная работа и передача небольших объёмов данных в реальном времени.

СВЯЗИ
STUN, TURN, ICE, SDP, DTLS, SRTP, RTP, UDP.
