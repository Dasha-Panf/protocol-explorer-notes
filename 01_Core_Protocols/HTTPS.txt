HTTPS — HTTP SECURE
Источник: Protocol Explorer, карточка HTTPS.

ПО САЙТУ
Назначение: защищённый обмен HTTP.
Порт: в карточке HTTP рядом с HTTPS указано 443.
Сценарий:
1. Secure request — браузер запрашивает https://.
2. DNS lookup — то же разрешение имени, что и при HTTP; сам DNS в описанном сценарии не зашифрован.
3. TCP handshake — соединение к порту 443.
4. TLS handshake — согласование ключей и проверка сертификата.
5. Encrypted exchange — HTTP внутри TLS records.
6. Page rendering — браузер показывает защищённое соединение.

ПОЯСНЕНИЕ
HTTPS — это HTTP, передаваемый через защищённый TLS-канал. TLS обеспечивает шифрование, контроль целостности и аутентификацию сервера на основе сертификата. Сертификат связывает имя сервера с открытым ключом и проверяется клиентом через доверенную инфраструктуру сертификатов.
При традиционном HTTPS поверх TCP сначала устанавливается TCP, затем выполняется TLS handshake, после чего прикладные данные HTTP передаются в зашифрованном виде. В HTTP/3 используется QUIC поверх UDP, где TLS 1.3 интегрирован в установление QUIC-соединения; поэтому нельзя считать, что любой HTTPS обязательно использует TCP.

ЧТО НЕ СКРЫВАЕТСЯ АВТОМАТИЧЕСКИ
Шифрование HTTP не означает сокрытие всех метаданных. IP-адрес назначения, объём и время передачи остаются наблюдаемыми. DNS может быть отдельным незашифрованным запросом, если не используется DoH/DoT или иной защищённый способ разрешения имён.

СВЯЗАННЫЕ ТЕМЫ
HTTP, TLS, DNS, DoH, TCP, QUIC, сертификаты, PKI.
