QUIC — HTTP/3 OVER UDP
Источник: Protocol Explorer, карточка QUIC.

ПО САЙТУ
Сценарий:
1. Choosing HTTP/3 — предыдущий визит сообщил браузеру, что сервер поддерживает HTTP/3.
2. Initial packets — Client Hello отправляется сразу.
3. Server Hello — затем сертификат, передаваемый в зашифрованном виде.
4. Finished + GET — запрос отправляется в пределах одного round trip в показанной последовательности.
5. The response — ответ передаётся в собственном потоке.
6. New network — соединение распознаётся по ID, а не только по сетевому адресу.

ПОЯСНЕНИЕ
QUIC — транспортный протокол, работающий поверх UDP и используемый HTTP/3. Он включает шифрование на основе TLS 1.3, мультиплексирование потоков и управление потерями/перегрузкой. Разделение потоков уменьшает проблему блокировки на уровне одного TCP-потока: потеря данных в одном QUIC stream не обязана блокировать доставку данных в другом.
Connection ID помогает идентифицировать соединение при изменении IP-адреса или порта, например при переключении сети Wi-Fi на мобильную.
QUIC не является просто «HTTP поверх UDP»: он реализует транспортные функции, которые в классическом стеке выполнял TCP, но встроенные в QUIC.

СВЯЗАННЫЕ ТЕМЫ
HTTP/3, UDP, TLS 1.3, TCP, миграция соединения.
