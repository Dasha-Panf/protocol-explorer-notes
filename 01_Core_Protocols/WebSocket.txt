WEBSOCKET — TWO-WAY WEB MESSAGING
Источник: Protocol Explorer, карточка WebSocket.

СЦЕНАРИЙ САЙТА
1. TCP CONNECTION — TCP-соединение к серверу, как для HTTP.
2. ASK TO UPGRADE — HTTP-запрос с Upgrade: websocket.
3. SWITCH PROTOCOLS — ответ 101: дальше используется WebSocket.
4. LIVE UPDATES — небольшие кадры передаются в обе стороны.
5. KEEPING IT ALIVE — Ping и Pong.
6. CLOSING — каждая сторона отправляет close frame.

ПРИНЦИП РАБОТЫ
WebSocket создаёт постоянный двунаправленный канал обмена сообщениями между клиентом и сервером. В классическом варианте RFC 6455 соединение начинается с HTTP/1.1 Upgrade handshake. После ответа 101 Switching Protocols стороны обмениваются WebSocket frames в рамках одного TCP-соединения.
В браузере незашифрованный вариант обозначается ws://, защищённый — wss://. В последнем случае канал защищён TLS. WebSocket frames поддерживают текстовые и бинарные сообщения, управляющие кадры Ping, Pong и Close.
WebSocket полезен для чатов, live-обновлений, совместных редакторов и приложений, где серверу нужно отправлять данные без повторного HTTP-запроса клиента.

ЧЕМ ОТЛИЧАЕТСЯ ОТ HTTP
HTTP обычно описывается моделью запрос–ответ. WebSocket после первоначального переключения предоставляет двусторонний обмен сообщениями. Сходство начального handshake не означает, что весь дальнейший обмен продолжает быть обычным HTTP.

БЕЗОПАСНОСТЬ
Для защищённого канала используется wss://. Серверу следует проверять Origin, а приложению — аутентификацию, авторизацию и корректность входных сообщений. Длительное соединение требует управления сессиями и лимитов ресурсов.

СВЯЗИ
