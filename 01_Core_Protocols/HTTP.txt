HTTP — HYPERTEXT TRANSFER PROTOCOL
Источник: Protocol Explorer; карточка HTTP и пример packet trace.

ПО САЙТУ
Описание: HTTP — протокол веба. Клиент запрашивает ресурс, например HTML-страницу; сервер отвечает кодом состояния, заголовками и обычно телом. В HTTP/1.1 обмен описан как запрос и ответ с читаемым текстом.
Уровень: Application (Layer 7).
Порт: 80 (для HTTPS на сайте указан 443).
Транспорт: TCP.
Формат: текст (заголовки + необязательное тело).
Методы, перечисленные сайтом: GET, POST, PUT, DELETE, HEAD.
Стандарты в карточке: RFC 9110, RFC 9112.

ПОШАГОВЫЙ СЦЕНАРИЙ САЙТА (5 ШАГОВ)
1. Client request — браузер готовит запрос. Для http://www.example.com/ используется GET; перед передачей нужно узнать IP-адрес, поскольку пакеты направляются к IP, а не к доменным именам.
2. DNS resolution — находится IP-адрес сервера.
3. TCP connection — устанавливается надёжное соединение.
4. HTTP exchange — передаются запрос и ответ.
5. Page rendering — браузер отображает содержимое.

ПРИМЕР ТРАССИРОВКИ ИЗ СНИМКА САЙТА
- 192.168.1.10 → 8.8.8.8: DNS A query www.example.com, 75 B.
- 8.8.8.8 → 192.168.1.10: DNS response A 203.0.113.10, 91 B.
- Клиент → 203.0.113.10:52344 → 80: TCP SYN.
- Сервер → клиент: TCP SYN, ACK.
- Клиент → сервер: TCP ACK.
- Клиент → сервер: HTTP GET / HTTP/1.1.
- Сервер → клиент: HTTP/1.1 200 OK (text/html), 9 segments, 12.8 KB.

ПОЯСНЕНИЕ
HTTP задаёт семантику запросов и ответов: метод, целевой ресурс, поля заголовков, код состояния и содержимое. GET обычно используется для получения представления ресурса; POST — для передачи данных, обрабатываемых целевым ресурсом; PUT — для создания/замены состояния по URI; DELETE — для удаления; HEAD — получение метаданных ответа без тела.
HTTP сам по себе не отвечает за разрешение DNS-имени и не устанавливает TCP-соединение. Это соседние операции стека. Современный веб может работать поверх HTTP/2 или HTTP/3; карточка сайта описывает текстовый HTTP/1.1 пример, поэтому его нельзя переносить на все версии HTTP без оговорок.

ВАЖНО
Обычный HTTP без TLS не обеспечивает конфиденциальность содержимого. Секреты и сессионные данные могут быть прочитаны или изменены на пути передачи. Для веб-трафика обычно используют HTTPS.

СВЯЗАННЫЕ ТЕМЫ
DNS, TCP, HTTPS, TLS, QUIC, HTTP/3, HTTP Proxy.
