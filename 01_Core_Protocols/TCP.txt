TCP — TRANSMISSION CONTROL PROTOCOL
Источник: Protocol Explorer, карточка TCP.

ПО САЙТУ
Сценарий:
1. Open connection — three-way handshake.
2. Send data — каждый байт нумеруется.
3. Two segments back — один из двух сегментов потерян.
4. A gap is noticed — duplicate ACK с SACK.
5. Resend the gap — повторно передаются только недостающие байты.
6. Close connection — каждая сторона завершает свою часть соединения.

ПОЯСНЕНИЕ
TCP — ориентированный на соединение транспортный протокол. Он предоставляет приложению упорядоченный поток байтов, обнаруживает потерю по номерам последовательности и подтверждениям и выполняет повторную передачу. TCP также регулирует поток данных и перегрузку сети.
Трёхстороннее установление соединения:
- SYN: клиент предлагает начальный номер последовательности.
- SYN-ACK: сервер подтверждает SYN клиента и сообщает свой начальный номер.
- ACK: клиент подтверждает SYN сервера.
После этого стороны могут передавать данные.
Номера последовательности относятся к байтам потока, а не просто к «номерам пакетов». ACK обычно указывает следующий ожидаемый байт. SACK (Selective Acknowledgment) позволяет сообщать о блоках данных, уже полученных за пределами пропуска, чтобы отправитель мог эффективнее повторять только отсутствующие диапазоны.
Закрытие обычно выполняется FIN/ACK с каждой стороны отдельно; RST используется для сброса соединения.

ВАЖНО
TCP гарантирует упорядоченный поток байтов между конечными точками при успешном завершении доставки, но не гарантирует, что приложение обработало данные или что удалённая бизнес-операция завершилась успешно. Сегментация потока может не совпадать с границами сообщений приложения.

СВЯЗАННЫЕ ТЕМЫ
UDP, HTTP, HTTPS, SSH, SMTP, DNS, QUIC.
