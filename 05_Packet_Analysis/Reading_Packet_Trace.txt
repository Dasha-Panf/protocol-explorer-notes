КАК ЧИТАТЬ PACKET TRACE В PROTOCOL EXPLORER

Видимые в табличном представлении колонки:
- No. — порядковый номер события/пакета в отображаемом сценарии.
- Time — время относительно начала сценария.
- Source — источник.
- Destination — назначение.
- Protocol — распознанный протокол.
- Info — краткое описание содержимого или флагов.
- Size — размер записи/пакета, указанный симуляцией.

Пример HTTP trace из доступного снимка:
1. DNS query A www.example.com от 192.168.1.10 к 8.8.8.8, размер 75 B.
2. DNS response A 203.0.113.10 от 8.8.8.8 к 192.168.1.10, размер 91 B.
3. TCP SYN от 192.168.1.10:52344 к 203.0.113.10:80.
4. TCP SYN, ACK в обратном направлении.
5. TCP ACK — завершение трёхстороннего handshake.
6. HTTP GET / HTTP/1.1.
7. HTTP/1.1 200 OK (text/html), указано 9 сегментов, 12.8 KB.

Как интерпретировать:
- DNS-пары показывают преобразование имени в IPv4-адрес.
- SYN, SYN-ACK, ACK — три сообщения установления TCP-соединения.
- После соединения приложение отправляет HTTP-запрос.
- HTTP 200 — успешный статус ответа; размер ответа и число сегментов описывают доставку содержимого.
- Времена в таблице — значения учебной симуляции, а не универсальные нормативы.

Обозначения TCP:
SYN — запрос синхронизации последовательностей при установлении соединения.
ACK — подтверждение.
FIN — инициирование штатного закрытия со стороны участника.
RST — аварийный сброс.
Seq — номер последовательности.
Ack — номер подтверждаемого байта/последовательности.

Ограничения:
Одна строка симуляции не всегда равна одному физическому Ethernet-кадру. Оффлоады сетевой карты, сегментация, агрегация, точка захвата и уровень декодирования могут менять вид представления в реальном анализаторе.
